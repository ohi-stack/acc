# Oru’Valen™ in ACC™ — Canonical Operating Model

**ACC baseline:** v1.3.0  
**Canonical domain:** `https://acc.onegodian.com`  
**Canonical Oru route:** `https://acc.onegodian.com/oru`

## Purpose

Oru’Valen™ is the O-H-I Twin / operational intelligence layer presented inside ACC. It provides continuity, context, lived-experience learning architecture, decision support, and a current-state model while preserving human authority.

ACC remains the execution control plane. OMOS remains the governed reasoning and Decision Record runtime.

## Canonical authority chain

```text
ONE / governing principles
→ human consciousness and authorized judgment
→ OneGodian / O-H-I framework
→ Oru’Valen context and continuity
→ OMOS governed reasoning
→ human gate
→ ACC authorized execution
→ tools / agents / integrations
→ measured outcome
→ proposed learning
```

## Five Oru intelligence systems

### 1. Institutional Memory

Authoritative OneGodian records, chronology, entities, systems, standards, and verified source material.

### 2. Lived Experience

Structured learning model:

```text
What happened
→ context / perception
→ decision
→ reason
→ action
→ outcome
→ lesson
```

### 3. Decision Memory

Stores problems, options, constraints, human choices, stated reasoning, actions, outcomes, and revisions.

### 4. Current-State Model

Represents what is true now: current priorities, active work, material constraints, unresolved commitments, risks, and verified system state.

### 5. Execution Intelligence

Transforms approved decisions into permissioned ACC tasks, workflows, deployments, and tool calls.

## Epistemic classes

Oru must keep these separate:

| Class | Meaning |
|---|---|
| FACT | Evidence-supported record |
| STATED POSITION | Explicit human statement, preference, intention, or correction |
| INFERENCE | Pattern-derived conclusion with evidence and confidence |
| PREDICTION | Forecast of likely preference or action; never authority |

Inference must not silently become fact. Prediction must not become authority.

## Learning loop

```text
LIVE
→ CAPTURE
→ VERIFY
→ CLASSIFY
→ REMEMBER
→ DETECT PATTERNS
→ PREDICT
→ RECOMMEND
→ ACT WITH AUTHORITY
→ MEASURE
→ LEARN
```

Outcome learning is required. Oru should not optimize only for stated intent.

## Agent separation

Oru’Valen is not registered as an external AI agent.

The ACC Agents registry remains for model-backed agents, tools, workers, automations, and executors that are permissioned through ACC.

The distinction is intentional:

```text
Oru’Valen = continuity + operational intelligence
Agent = bounded executor / worker
ACC = control plane
OMOS = governed reasoning
Human = final authority
```

## Action authority

### Low risk

May be automated when authorized:

- research;
- drafting;
- classification;
- documentation;
- analysis;
- repository inspection;
- testing;
- non-destructive status checks.

### Medium risk

Requires defined permission:

- publishing;
- editing production content;
- repository writes;
- scheduling communications;
- CRM updates;
- customer-facing changes.

### High risk

Requires explicit human approval:

- funds movement;
- binding legal execution;
- production credential changes;
- ownership changes;
- destructive database operations;
- real-property transfers;
- securities-related activity;
- final commercial concessions;
- irreversible infrastructure changes.

## Production rule

A future Oru capability must not be labeled Operational or Production merely because its UI exists. It must be implemented, documented, repeatable, permissioned, and verified against the canonical environment.
