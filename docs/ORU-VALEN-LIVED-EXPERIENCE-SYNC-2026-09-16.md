# ACC ↔ Oru’Valen ↔ OMOS Lived Experience Sync

**Effective:** 2026-09-16  
**ACC:** `https://acc.onegodian.com`  
**OMOS:** `https://omos.onegodian.com`  
**Oru private module:** `ohi-stack/acc-oruvalen`

## Responsibility split

- **Oru’Valen™** — personalized O-H-I Twin and approved continuity/context layer.
- **OMOS™** — governed reasoning, Council synthesis, Human Gate, Decision Records, provenance, persistence, and audit/history.
- **ACC™** — authorized execution control plane for approved tools, agents, workflows, connectors, deployments, verification, and external actions.

Oru is not an external AI agent and must remain distinct from ACC’s Agents registry.

## Canonical governed flow

```text
Human input or authorized evidence
→ Oru context snapshot
→ OMOS governed reasoning
→ Council / synthesis
→ Human Gate
→ Decision Record
→ ACC authorized execution
→ Verification / audit
→ Outcome
→ Proposed Oru learning
→ Human-approved memory/current-state update
```

## Lived Experience

The Twin may represent approved real-world context using explicit record classes. The model does not imply continuous observation or background surveillance.

Primary memory classes:

- Institutional Memory
- Lived Experience
- Decision Memory
- Behavior & Routine
- Relationship Context
- Economic Reality (restricted)
- Preferences & Judgment
- Lessons & Operating Rules
- Current-State Model

## Epistemic discipline

All material human-state records must remain classified as one of:

- `FACT`
- `USER_STATEMENT`
- `INFERENCE`
- `PREDICTION`

Inference or prediction may not silently become fact. Direct human correction has higher authority than a prior model inference about that human.

## Privacy and authority

- Human authority remains final.
- Authorized sources only.
- Connector read access does not imply write authority.
- Restricted financial, health, legal, identity, private-contact, and credential categories require access controls and purpose limitation.
- Raw passwords, API keys, private keys, seed phrases, session secrets, and equivalent credentials are prohibited from durable Oru memory.
- Consequential execution remains subject to OMOS/Human Gate authorization and ACC policy checks.
- Durable memory/current-state mutation must be attributable, versioned, reviewable, and approval-gated.

## Outcome learning

ACC should return normalized execution outcome provenance to OMOS. Oru may then create a **learning proposal** containing supporting events, Decision Records, execution outcome references, proposed change, confidence, privacy class, conflicts, and approval state.

A learning proposal is not an automatic self-rewrite.

## Maturity rule

Repository implementation, merge, deployment, and production proof remain separate states. The console may describe integration targets, but automatic approved-source retrieval, automatic memory injection, execution handoff bound to Oru provenance, outcome ingestion, durable Current-State editing, and the complete digital-twin loop must not be represented as Production until independently verified.
